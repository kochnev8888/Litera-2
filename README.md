# Шрифты от ИИ · Литера

Рабочий веб-прототип командного проекта «Шрифты от ИИ». Из описания пользователя студия подбирает три стилистических варианта, показывает набор, позволяет изменить параметры и собрать TrueType-файл. Второй сценарий начинается с загрузки существующего TTF или OTF: сервер измеряет его геометрию и открывает в студии.

Проект вырос из демо «Литера»: сохранены прежние маршруты и интерфейс, а внутри добавлены ИИ-слой и расширенная обработка контуров.

Репозиторий: [github.com/kochnev8888/Litera-2](https://github.com/kochnev8888/Litera-2)

## Как скачать и посмотреть

Самый простой способ — клонировать репозиторий:

```sh
git clone https://github.com/kochnev8888/Litera-2.git
cd Litera-2
```

Либо на странице репозитория нажмите **Code → Download ZIP** и распакуйте архив.

Дальше установите зависимости и запустите сервер (см. раздел «Запуск» ниже) — интерфейс откроется в браузере по адресу `http://127.0.0.1:8765`.

## Запуск

Нужен Python 3.10 или новее. Из папки проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B server.py
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Для другого порта добавьте `--port 9000`. На Windows используйте `py -m venv .venv` и `.venv\Scripts\python.exe`.

`skia-pathops` нужен для булевых операций (контраст и добор насыщенности за пределами вариативной оси). Без него базовое преобразование ширины, наклона, метрик и скругление углов продолжает работать. `ttfautohint` — системная утилита; если она установлена, сервер автоматически запускает хинтинг при экспорте.

## Что добавлено к прототипу

- **ИИ-слой** (`ai_service.py`): LLM превращает текстовый запрос в параметры гарнитуры и возвращает три различимых варианта. По умолчанию используется локальная Ollama и установленная модель `qwen2.5:3b`; если Ollama недоступна или модель не ответила, работает детерминированный эвристический парсер.
- **Core Domain Schema** (`font_schema.py`): единый Pydantic-контракт параметров и метрик. Сетка `units_per_em = 1000`, `ascender = 800`, `descender = -200` фиксируется бэкендом.
- **Геометрический анализатор** (`font_analyzer.py`): измеряет толщину ствола H, контраст по O, ширину, наклон, высоту строчных/прописных и наличие засечек. Значения нормализуются к сетке 1000 units-per-em.
- **Синтез и препресс** (`font_synthesis.py`): выбор эталонной гарнитуры по стилю и засечкам, инстанцирование вариативной оси `wght`, аффинное масштабирование ширины, сдвиг для наклона, нелинейное масштабирование по Y для `x_height` / `cap_height`, контраст и скругление углов через `skia-pathops`, нормализация направления контуров.
- **Сборка OpenType**: таблицы `head`, `hhea`, `maxp`, `OS/2`, `name`, `cmap`, `post`; корректные `usWeightClass`, `usWidthClass`, `sxHeight`, `sCapHeight`, `ulCodePageRange1` с битом кириллицы, `post.italicAngle`, уникальный PostScript Name. При наличии `ttfautohint` добавляется хинтинг.
- **Хранилище исходников** (`font_storage.py`): загруженный файл получает `base_font_id`, поэтому студия продолжает работать с исходными контурами между запросами.

## Сценарии интерфейса

1. **По описанию.** Введите запрос или выберите пресет («Журнал», «Интерфейс», «Терминал»). Сервер вернёт три варианта с именами и описаниями. Первый вариант открывается в студии.
2. **Студия.** Слайдеры: насыщенность, ширина, трекинг, наклон, контраст, скругление, острота, высота строчных. Переключатель засечек и стиль окончаний. Живой предпросмотр пересобирает TTF на сервере и подключает его через `FontFace`.
3. **Из файла.** Загрузите TTF/OTF до 10 МБ. Сервер покажет семейство, формат, число глифов, определённые насыщенность, ширину, наклон, контраст, `x-height` и засечки. Кнопка загрузки сразу открывает шрифт в студии.

## API

Старые маршруты сохранены, новые соответствуют техническому заданию.

| Запрос | Вход | Результат |
| --- | --- | --- |
| `GET /api/health` | — | Статус сервера |
| `POST /api/recommend` | JSON `{prompt}` | Три варианта с параметрами и метаданными |
| `POST /api/v1/ai/font-style` | JSON `{prompt, variants_count}` | `{mode, variants}` |
| `POST /api/import` | Файл в теле запроса | Профиль шрифта + `base_font_id` |
| `POST /api/v1/fonts/analyze` | Файл или `multipart/form-data` | Профиль шрифта + `base_font_id` |
| `GET /api/v1/fonts/base/{preset}` | — | Нейтральные параметры эталонной гарнитуры |
| `POST /api/preview` | JSON с параметрами или старые query-параметры | TTF для предпросмотра |
| `POST /api/export` | То же + `family_name` | TTF с заголовком скачивания |
| `POST /api/v1/fonts/generate` | JSON `GenerateRequest` | TTF или WOFF2 |

Пример запроса генерации:

```json
{
  "parameters": {
    "weight": 800,
    "width": 85,
    "slant": 8,
    "contrast": 0.75,
    "roundness": 0.2,
    "sharpness": 0.9,
    "serif": false,
    "terminal_style": "flat",
    "stroke_contrast_axis": "vertical",
    "x_height": 520,
    "cap_height": 720,
    "overshoot": true,
    "ink_trap": false,
    "mood": "aggressive",
    "style": "cyberpunk",
    "purpose": "print",
    "language_support": ["latin", "cyrillic"]
  },
  "metrics": {"units_per_em": 1000, "ascender": 800, "descender": -200},
  "family_name": "Cyber Condensed Heavy"
}
```

Для модификации загруженного шрифта добавьте `base_font_id` и `base_parameters`, полученные из `/api/import` или `/api/v1/fonts/analyze`.

## Локальная Ollama и qwen

По умолчанию ИИ-слой обращается к локальной Ollama:

- адрес: `http://127.0.0.1:11434` (нативный API `/api/chat`);
- модель: `qwen2.5:3b`.

Проверьте, что Ollama запущена и модель установлена:

```sh
ollama list             # в списке должна быть qwen2.5:3b
ollama serve            # если сервис ещё не запущен
ollama pull qwen2.5:3b  # только если модели нет
```

Переопределить адрес или модель можно переменными:

```sh
export OLLAMA_HOST=http://127.0.0.1:11434
export OLLAMA_MODEL=qwen2.5:3b
.venv/bin/python -B server.py
```

Первый ответ `qwen2.5:3b` может занимать 10–20 секунд в зависимости от машины; интерфейс показывает состояние «Подбираем…». Если Ollama недоступна, сервер автоматически переходит на эвристику. Для принудительного отключения LLM используйте `FONT_AI_DISABLE_LLM=1`.

При необходимости можно подключить внешний OpenAI-совместимый API — переменные `OPENAI_BASE_URL`, `OPENAI_API_KEY` и `OPENAI_MODEL` имеют приоритет над Ollama. Опциональный FastAPI-фасад с тем же эндпоинтом находится в `font_module.py`.

## Ограничения текущей версии

- Контраст реализован как утоньшение/утолщение горизонтальных штрихов через `skia-pathops`; кривые (например, верх и низ O) меняются меньше, чем прямые перекладины.
- Засечки не синтезируются: гарнитура выбирается из эталонных семейств с засечками или без. Для загруженного шрифта переключатель засечек фиксирует исходный стиль.
- Перенос исходного кернинга, лигатур и всех вариативных осей в экспортируемый файл не выполняется: сборщик пересобирает контуры и горизонтальные метрики.
- Готовность к печати проверяйте в конкретном офисе (MS Word, LibreOffice) и в RIP; для этого в `OS/2` заполняются кодовые страницы, а при наличии `ttfautohint` добавляется хинтинг.

## Проверка

```sh
python3 -B -m unittest discover -s tests -v
```

Тесты проверяют эвристику ИИ, геометрический анализ, сборку обязательных таблиц, кириллицу, `italicAngle`, метрики и круговой сценарий «сгенерировать → проанализировать».

## Лицензии

Базовые варианты используют Lora, IBM Plex Sans и JetBrains Mono. Лицензии SIL OFL входят в `static/fonts/`. При экспорте производного шрифта сервер сохраняет текст лицензии исходной гарнитуры в таблице `name`.
